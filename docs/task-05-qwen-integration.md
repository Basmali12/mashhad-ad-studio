## Sources and runnable boundary

The official [Qwen repository](https://github.com/QwenLM/Qwen-Image) and [2511 model card](https://huggingface.co/Qwen/Qwen-Image-Edit-2511) specify `QwenImageEditPlusPipeline`. The software uses the original BF16 model, not a quantized, Lightning or third-party checkpoint. Model revision `6f3ccc0b56e431dc6a0c2b2039706d7d26f22cb9`, source revision `6b5e1f5cec987d404be5ac6657db3b9aacb56a89`; the 34-file manifest totals 57,720,461,873 bytes (53.75637 GiB). Large weights were inspected only through public size/hash metadata; public configuration/tokenizer text was streamed for hash verification without retaining a model copy. See `task-05-qwen-runtime.md` for dependency compatibility, source URLs and manifest evidence.

`engine/qwen/` is a real lazy Python inference and explicit CPU preparation/deployment implementation. It accepts one to three images plus text, 40 steps, true CFG 4, guidance 1, fixed seed and original 720×1280 / 1280×720 output. It fails on unexpected dimensions rather than silently rescaling originals. Inference uses local-only weights; opening administration cannot download or initialize a model. All installation/readiness claims in this task concern code, not real cloud readiness or measured VRAM.

## Integration surfaces

- `qwen-prompt.mjs`: structured reference-to-character mapping, story event, action, location, era, lighting, camera, expression, pose and style. Wardrobe changes need an explicit story reason; stable face/body/age/props are retained. Visible lettering is opt-in. These are conditioning instructions, not guarantees.
- `qwen-integration.mjs`: independent model profile, account/namespace selection and production adapter. The existing FLUX image execution/billing/recovery coordinator is parameterized for model metadata and reused rather than copied. FLUX remains an independent engine.
- `qwen-modal-transport.mjs` and the shared transport/bridge: closed server-owned model selection, private encrypted credential use, pinned manifests, durable idempotent operations, no automatic fallback or retry. Qwen operations/results/runtime/preparation and model paths do not mix with FLUX, even on the same account.
- `production-plan.mjs`: with both adapters registered, the first new identity is generated by FLUX; later angles and scenes use Qwen and depend on that identity image. Existing character reference inputs route directly to editing. Shot order and chapter/timeline contracts are retained. Explicit per-character wardrobe/expression/pose edits are scoped to a shot and do not rewrite the Character Bible.
- `production-models.mjs`: preflight reads/validates owned input images before GPU admission. It retains the same quote, approval, metering, stop confirmation and partial-result recovery rules. Preflight failure before dispatch has no inference spend.
- `flux-image-assets.mjs` and `image-quality.mjs`: shared original/preview persistence, edited-image lineage, tenant ownership and character-reference library; structural and optionally local visual review; safe handoff to a future animation adapter.

The service has a separate `FILM_QWEN_PAID_ENABLED=NO` default. Both that flag and existing server-side paid authority, quotes, account/file readiness and explicit approval must permit an operation. It does not enable itself from a browser flag. The conservative Qwen preflight currently admits RTX PRO 6000 with minimum 96GiB VRAM, 128GiB host RAM and CPU 4; these are unmeasured guardrails, not an empirical guarantee or an account-availability claim. L40S is not silently substituted. No actual environment flag was changed.

## Identity and review policy

Each image retains model/version/revision, exact final prompt/settings, source references, root lineage and character/project/shot links. Existing approved anchors are preferred; an initial FLUX reference may be used as an explicitly uncertified editing input. The system does not regenerate identity from text when an image is available, and it rejects more reference images than the configured runtime supports rather than silently dropping a character.

Structural validation verifies dimensions, immutable original bytes, scope and character/reference assignment. Visual claims such as face match, people count, anatomy, props and random text require a trusted local visual inspector or explicit human review. Without an inspector they remain **unverified**, never a fabricated pass. Failed checks retain a review record and do not trigger paid regeneration. Explicit owner/admin human approval records its provenance and does not assert automated certification. Animation handoff requires current hash-matched review approval and approved character anchors. Qwen/Wan handoff is an opaque owned asset contract; Wan itself is not installed in this task.

The current UI design/files layout is unchanged. Review services are server-side contracts for subsequent approved interface wiring. No new public endpoint trusts an actor, file path, image quality score, token or model manifest from the browser.
