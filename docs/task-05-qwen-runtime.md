- مستودع الناشر: [QwenLM/Qwen-Image](https://github.com/QwenLM/Qwen-Image/tree/6b5e1f5cec987d404be5ac6657db3b9aacb56a89)، commit مثبت `6b5e1f5cec987d404be5ac6657db3b9aacb56a89`.
- الإصدار المحلي `2511`، والمسار `QwenImageEditPlusPipeline`، والأوزان BF16 الأصلية. لا quantization أو Lightning أو تغيير خطوات لتحقيق سرعة مفترضة.
- [بطاقة الناشر](https://huggingface.co/Qwen/Qwen-Image-Edit-2511/blob/6f3ccc0b56e431dc6a0c2b2039706d7d26f22cb9/README.md) تحدد Apache 2.0 وتعرض مسار التعديل بالمراجع، أربعين خطوة و`true_cfg_scale=4.0` و`guidance_scale=1.0` وnegative prompt مسافة واحدة. نقلت الإعدادات إلى التنفيذ ولم أنفذ المثال.

## Manifest والحجم

`engine/qwen/model-manifest.json` يثبت **34 ملفاً**، بمجموع **57,720,461,873 بايت، نحو 53.75637GiB**. يتضمن Transformer بخمسة أجزاء، مرمز النص/الرؤية بأربعة أجزاء، VAE وScheduler وTokenizer وProcessor وإعداداتهم وREADME الذي يذكر الترخيص. لا يوجد checkpoint إضافي أو GGUF أو LoRA ضمن المسار.

مصدر الأحجام وبصمات الأوزان [واجهة Hugging Face الوصفية للمراجعة المثبتة](https://huggingface.co/api/models/Qwen/Qwen-Image-Edit-2511/revision/6f3ccc0b56e431dc6a0c2b2039706d7d26f22cb9?blobs=true). لم تقرأ أي safetensors. ملفات LFS الكبيرة، ومنها `processor/tokenizer.json`، أخذت SHA256 الخاصة بها من metadata فقط.

يختلف هذا النموذج عن FLUX: مجلد tokenizer الجذري لا يحتوي `tokenizer.json` مكتملة، لذلك يلزم `merges.txt` و`vocab.json` إضافة إلى Processor. ملفات النص/الإعداد المنشورة غير LFS توفر Git SHA1 فقط؛ جرى بثها في الذاكرة لحساب SHA256 والتحقق المستقل من Git blob ID، دون حفظ نسخة محلية منها. شمل ذلك ملفات tokenizer وفهرس Transformer ذي 198KB، وبموافقة منسق المهمة على قراءة الإعدادات العامة فقط. لا يعني ذلك تنزيل أوزان النموذج أو تهيئة Volume.

## التنفيذ والقيود

`runtime.py` يعرّف `QwenEditRuntime`، مع `prepare()` و`generate(request, output_dir, on_progress)`. استيراد الوحدة يقرأ manifest محلياً فقط؛ Torch وDiffusers يستوردان داخل `prepare()` عند الاستدعاء المصرح به مستقبلاً.

- `QwenImageEditPlusPipeline.from_pretrained(..., local_files_only=True, torch_dtype=torch.bfloat16)`.
- CPU offload محفوظ، مع إعادة استخدام Pipeline داخل نفس instance بين التعديلات. لا إعادة بناء لكل صورة ولا تفعيل torch.compile أو FP8 أو نموذج بديل.
- صورة مرجعية واحدة إلى ثلاث صور؛ المراجع bytes فقط، وليست URLs أو مسارات يرسلها المتصفح. يحفظ ترتيبها إلى Pipeline.
- الأنماط `edit` و`multi_reference`؛ النص وحده لا يقبل كتوليد T2I في هذا المحرك.
- 40 خطوة، guidance ‏1.0، true CFG ‏4.0، وصورة واحدة للطلب. لا يسمح للعميل بتغيير هذه الإعدادات ضمن RPC.
- الخرج حصراً 720×1280 أو 1280×720. يتحقق التنفيذ من أبعاد الناتج ويرفض أي انحراف؛ لا يعوضه بقص أو تصغير خفي بعد التوليد.
- PNG الأصلي محفوظ مع SHA256 وseed وإعدادات التعديل وأزمنة التحميل والاستدلال، وذروة ذاكرة Torch حين تكون مقاسة فعلياً. التقدم من callbacks الحقيقية ذات الأربعين خطوة، لا عداد زمني وهمي.

فحص [مصدر Diffusers المثبت](https://github.com/huggingface/diffusers/blob/v0.42.1/src/diffusers/pipelines/qwenimage/pipeline_qwenimage_edit_plus.py) أكد دعم image list وwidth/height وcallbacks وQwen2.5-VL، كما أن المراجعة المثبتة من VAE تستخدم عامل محاذاة فعلياً مقداره 16 للصورة؛ الأبعاد المطلوبة تقبله. المعالجة الداخلية لصورة الشرط في الموديل لا تعني أن برنامجنا غيّر أبعاد PNG الناتج.

هذه آلية تعديل موجه بالصورة، وليست ضماناً رياضياً لثبات الوجه أو العمر أو الملابس أو الدور. جودة المراجع وتفاعل النص معها يجب اختباره بصرياً بعد موافقة منفصلة.

## الاعتماديات والموارد

النسخ المباشرة مثبتة: Python 3.12، PyTorch `2.9.1+cu128`، Torchvision `0.24.1+cu128` المطابق له من الفهرس الرسمي، Diffusers `0.42.1`، Transformers `5.22.1`، Accelerate `1.15.0`، Safetensors `0.8.0`، Pillow `13.0.0`، Hugging Face Hub `2.4.0`، Tokenizers `0.23.1`، NumPy `2.2.6` وModal SDK `1.6.2`.

الـProcessor المثبت يحدد ImageProcessorFast، لذلك أضيف Torchvision في صورة Qwen فقط. لم يغيّر ملف اعتماديات FLUX. يتوقع المسار دعم CUDA/BF16؛ ولم ينفذ resolver كامل أو تثبيت wheels أو استدلال حي هنا. تثبيت الإصدارات المباشرة ليس lock شاملاً ببصمات كل اعتماد متعدٍ.

الإعداد المحافظ للتجربة الأولى: RTX PRO 6000 بذاكرة 96GB وCPU ‏4 وRAM ‏128GiB، مع CPU offload. يمنع مصنع التطبيق اختيار L40S أو RAM أقل من 128GiB في هذا المسار الحالي. هذه **سياسة احترازية غير مقاسة**، وليست إعلاناً بأن النموذج يتطلب هذه الحدود عالمياً أو أن نجاحه عليها مضمون. تقييم VRAM الفعلي ووقت الإقلاع والسرعة والكلفة ينتظر اختباراً مصرحاً به.

الحدود الافتراضية: GPU call ‏600 ثانية، إقلاع 180 ثانية، خمول 1200 ثانية، `min_containers=0`, `max_containers=1`, `retries=0`. يتطلب رفعها عرض تكلفة وموافقة عبر البنية المشتركة؛ لا يوجد رفع تلقائي للمعالج أو إعادة عند OOM.

## Modal والتجهيز

الحزمة مستقلة في `engine/qwen/` وتعيد استخدام عقد البنية العامة المثبتة؛ لم تغير ملفات FLUX أو المحفظة أو السجلات أو النطاقات.

- `build_qwen_app(config, sdk=None)` يعيد التطبيق و`QwenEngine`، مع معامل `runtime_id`.
- اسم التطبيق `mashhad-qwen-<12 حرفاً من UUID التعريف>`؛ Volume نتائج منفصل `mashhad-qwen-results-<بصمة التعريف>`.
- `start(scope)` و`generate(request, scope)` يتحققان من الحساب والمحرك والجلسة ومعرف الطلب. لا يستخدم status استدعاء GPU لمجرد قراءة الحالة.
- الأوزان تركب read-only على GPU. تجهيز CPU وحده يكتب ملفات النموذج ويطابق SHA256 قبل `READY.json`.
- `prepare_models(request)` يحتاج موافقة وبصمة manifest ومراجعة ونطاقاً مطابقاً. مواصلة مراقبة العملية لا تعيد تنزيلها أو تشغيلها.
- `deploy_qwen_app(packet, client=...)` bootstrap صريح بعد الموافقة فقط؛ لا يعمل عند الاستيراد أو start كحل تلقائي، ويرفض استبدال تطبيق أو Volume نتائج لم تثبت ملكيتهما. البناء والتخزين والشبكة قد تضيف تكاليف إلى حوسبة التجهيز ويجب ذكرها في العرض.
- دالة تجهيز CPU محددة بـ2CPU و8GiB و3600 ثانية مع إقلاع 180 ثانية، دون GPU. لا تستخدم مساحة HostHatch لنقل الأوزان.

يحفظ التجهيز `preparations/<operationId>.json` بحجم الملفات المتحققة فعلياً؛ لا يدعي نسبة نقل داخل ملف لم يقسها. الطلب المكرر يعيد النتيجة المسجلة أو الحالة المجهولة دون إعادة تلقائية.

يحفظ توليد الصورة PNG وreceipt في `runs/<runId>/results/<requestId>.png/json`، وتقدم الخطوات في `runs/<runId>/progress/<requestId>.json`. معرف طلب ثابت مع بصمته يمنع توليد الصورة مرتين بسبب إعادة القراءة أو انقطاع الواجهة.

تعريفات Modal في نطاق Python العام، لا nested serialized functions، حتى لا تنقل bytecode بين Python المحلي وصورة Python 3.12. اختبار SDK الحقيقي تحقق من التسجيل فقط دون hydration أو بناء أو نشر.

## ما ثبت وما ينتظر

`test_qwen_runtime.py` يستخدم مكونات صغيرة وصور PNG اصطناعية وPipeline محقوناً: التعديل بمرجع ومرجعين وثلاثة بالترتيب؛ الإعدادات الأصلية و40 callback؛ العمودي والأفقي ورفض تغير الأبعاد؛ منع الطلبات والمسارات غير الآمنة؛ إعادة استخدام Pipeline؛ علامة الجاهزية والحساب؛ تجاوز الملفات السليمة؛ منع المحاولة المكررة؛ وتسجيل التطبيق محلياً.

بانتظار موافقة: بناء صورة حقيقية واختبار الاستيراد، تنزيل 53.75637GiB، تشغيل GPU، جودة الهوية والأحداث والإضاءة، VRAM/RAM، الزمن والكلفة، الإلغاء والإيقاف المؤكد، وتجربة تعديل شخصية حقيقية ببيانات مرخصة. لا تمثل نتائج الاختبارات المحقونة إثباتاً لهذه النقاط.
