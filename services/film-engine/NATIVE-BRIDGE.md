# Native Studio bridge integration

Native Google OIDC and SQL sessions supply the trusted ctx.actor. filmIdentity.actor reads that stable native user ID; platform administrator status comes only from the verified server allowlist. Browser project/device selectors confer no role. Public filmIdentity.ownAccess returns only {isAdmin}.

`api.filmBridge.request({operation,input,requestId})` is a Node action. It accepts only the frozen v1 operations in `engine/film-contracts.ts` and `bridge-contract.json`. Input fields are checked per operation before networking. Actor, role, URL and transport headers cannot be supplied by the browser. All `admin.*` operations reject non-administrators before a network call. Credential format errors return a fixed safe Arabic message; inputs, signatures, credentials and external errors are never logged by the bridge.

The native Studio server needs `FILM_BACKEND_ORIGIN` (fixed HTTPS origin only), `FILM_BRIDGE_SECRET` (independent random secret of at least 32 characters, shared only with the gateway), and the existing `IRAQ_AI_SUPER_ADMIN_EMAILS` allowlist. None is a `VITE_` variable. No credentials or cloud environment values were configured during local implementation. Keep the engine feature and paid-action flags disabled until separately approved. Never reuse the engine vault master key as the bridge secret.

Requests use exact raw JSON HMAC-SHA256 as specified in `BRIDGE-CONTRACT.md`. Redirects are rejected. The single attempt has a 25-second deadline spanning fetch and response reads; request and response bodies are bounded to 256 KiB. Network errors, unknown responses and deadline expiration return `{error:'REQUEST_STATE_UNKNOWN',message,followExisting:true}`. This does not mean a paid request failed. Use the existing project's `project.follow`, persisted text status, rental status, or administrator operation status. Do not automatically repeat start, text, prepare, test or generate with a fresh ID. Browser close does not stop a rental. No bridge action changes existing tool wallets or ledger tables.

Customer outputs are projected to the frozen DTO fields even for an administrator opening the customer pane. Display strings redact supplier names, credentials and private diagnostics. Opaque signed media URLs retain their exact bytes and must be HTTPS private-ticket URLs. Administrator responses preserve supplier identity and credential field labels while dropping credential values, endpoints and raw trace fields. No client computes settlement amounts; the gateway's numeric wallet values pass through unchanged.

React consumers can use `FilmOperation`, `FilmWallet`, `FilmServer`, `FilmRental`, and `FilmProject` from `services/film-engine/engine/film-contracts.ts` with the above native typed operation names. Handle `{error,message,followExisting}` before reading success DTO fields. `referenceUpload` is true only when exact allowed media origins are configured; signed direct upload/view tickets bypass the operation payload limit without sharing service secrets. `ingredients:false` and `voiceCloning:false` remain explicit. Whole-film merge and server-owned last-frame continuity remain separate supported capabilities.

Run `npx tsx scripts/verifyFilmBridge.ts`, `npm run verify:auth-redirect`, `npm run verify:billing`, `npm run lint`, and `npm run build`. Bridge tests execute the actual registered action and identity query handlers with local auth/database context fixtures and mocked external fetch, and validate signatures with the real gateway verifier. Real Google sign-in, deployed native session identity, cloud TLS, supplier billing/resource shutdown and live credentials are **not tested** by these local checks. No deployment, production database migration or paid request is part of this implementation.
