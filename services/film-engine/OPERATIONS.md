# Operations after inference retirement

## Current mode

There is no active film inference model. Retired LTX profiles and their runtime must not be installed again through old maintenance recipes. Do not retain or create a rollback copy of the retired model implementation for this task. No replacement engine, model download or paid job is authorized by these instructions.

Keep service management, authentication, encrypted account storage, PostgreSQL, the wallet ledger, media access, scheduling, provider metadata and safe stop/reconciliation available. A previously stored model-ready flag is historical information, not permission to start an absent engine. New model preparation requires an explicitly configured approved manifest; an empty/unconfigured manifest must not report success or create a Volume.

## Server inspection and deletion safety

1. Confirm HostHatch server identity `muhtaj-app` before maintenance; do not change the former Hostinger server.
2. Inventory service units, process working directories, container images/mounts, database references, Modal account/workspace IDs and Volume contents before deletion.
3. Delete only resources proven exclusively owned by the retired engine. A resource name containing the old model name alone is not sufficient if other applications reference it.
4. Preserve account credentials, vault/master keys, bridge keys, domain/Caddy configuration, user media and all financial/audit records. Do not print environment files or tokens.
5. Verify that no active customer job is using a resource before removing it. Unknown ownership or running-work state blocks that deletion; do not mark it complete.
6. Old engine-only server backups may be removed only after inspecting their contents and confirming no shared data. Do not create a new backup or restore point for this task.
7. Scoped cancellation must use recorded application/job identity and verify termination. Browser close or killed local wait does not prove stopped cloud resources.

No instructions here automatically delete cloud resources. Record actual checked and removed IDs separately from candidates; never equate local code removal with cloud cleanup.

## Deployment boundaries

Retain existing `iraqaistudio.com` and `scan.iraqaistudio.com` origin/routing configuration. Do not edit DNS, move domains, replace the shared database or remove scheduler/publishing/storage services. Apply source changes only after an idle/safe server preflight; do not run inference as a deployment test.

Keep `ENGINE_MASTER_KEY` separate from the database and `FILM_BRIDGE_SECRET`; neither is public/VITE configuration. HTTPS, exact-origin restrictions, backend administrator checks, tenant media authorization, replay prevention and integer microUSD settlement remain required.

## Free verification

Run local backend/gateway tests, root TypeScript/lint and both production builds. Verify the negative path: requesting the removed engine must not call the provider, create a Volume or debit a new compute charge. Verify positive preserved boundaries: account verification, encrypted persistence, permissions, existing media access, wallet history, metadata observation and scoped stop/reconciliation.

Any live cloud deletion or installed-service status must be reported from actual evidence. Test fixtures and local builds do not prove that HostHatch or Modal cleanup ran.
