# Film platform operations and release boundary

## Non-destructive retirement and credential unlink

Administrators explicitly confirm `admin.slot.retire({id,approved:true})`. This permanent state locks/unpublishes the row, preserves its rate/history and requires every account rental and source/destination resource record to be confirmed stopped first. It never performs an implicit stop or deletes a cloud object. Retired rows cannot be edited, reopened, tested or published. At most two **nonretired** slots may exist; replacements inherit from an active slot, never an old retired profile.

After all slots retire, `admin.account.unlink({accountId,approved:true})` invokes the existing engine credential removal path. A shared store transaction protects deletion against a new slot/rental/job. The primary source is always protected. Explicitly whitelisted non-secret metadata remains in `account-archive`; encrypted provider/HF credentials and a matching current selection are removed. Projects, credit/ledger records, rental rates, retired slots and local media remain intact. No Volume/app/model/video is deleted, and the provider token is **not remotely revoked**. Only recorded operations are checked; this is not a claim of a provider-wide resource inventory or zero external storage charges.

## Final local audit additions

Emergency stop now covers recorded standalone administrator samples and CPU preparation as well as customer rentals. It persists a stop-group ID, requests cancellation once per root session, follows with read-only reconciliation, and keeps unconfirmed resources busy. Slot selection follows saved same-slot/account test proof. Internal trusted cancellation has a per-job queue so it does not wait behind unrelated slow discovery. Shutdown attempts cancellation of every recorded unconfirmed resource, including failed standalone jobs; neither shutdown nor process exit is itself evidence of provider zero. Failed/completed-but-unconfirmed jobs retain account/source credential access and block new dispatch/unlink until reconciliation confirms stopped. No real provider shutdown was tested.

Private MP4 GET/HEAD supports real single byte ranges for browser seeking. Invalid/multiple/out-of-bounds ranges receive 416. Authorization/origin/expiry checks run before serving bytes; an expired ticket gets no media. The UI explains renewal and retains playback position without paid regeneration. Actual HTTP bytes/ranges were tested locally; generated cloud video playback and long-movie behavior still require staging.

Commercial policies requiring owner acceptance before customer release: credit expires 30 days after each individual manual topup, rather than on a shared calendar date; admission needs at least four minutes of funds with a stop guard, not merely a balance above one cent. Customer sale prices remain operator-defined and differ from supplier cost. These choices must not be advertised as a guaranteed invoice ceiling.

This package is local implementation, not a deployed or GPU-validated service. All tests isolate the supplier behind a fake boundary and use new temporary SQLite databases. No account credentials were configured, no API call/image build/GPU start/model download/production migration/deployment was performed. The old HostHatch service and historical customer data are outside this package.
