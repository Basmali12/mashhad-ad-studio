# مشهد — المرحلة الثالثة: البيانات وWorker Flow المحلي

استكمال مشروع المرحلة الأولى نفسه بـReact + TypeScript + Vite مع الحفاظ على العربية وRTL والوضعين. نُفذت تجربة Flow واحدة على Development، عبر Worker محلي وجلسة Chrome مخصصة. لم تُنشَر واجهة Production أو GitHub.

## المشروع الحالي

- Convex: `mashhad-ad-studio` في فريق `ali-basm`.
- بيئة التطوير: `dev:capable-cuttlefish-575`.
- Clerk: `Mashhad Ad Studio`، نسخة Development، تسجيل دخول عربي عبر Google أو البريد.
- `OWNER_SUBJECT` و`CLERK_JWT_ISSUER_DOMAIN` على خادم Convex يحددان المالك الوحيد. لا توجد جداول تجار أو اشتراكات أو زبائن.
- `.env.local` محلي ومتجاهل من Git؛ يحتوي عناوين المشروع والمفتاح العام فقط. لا يوجد مفتاح سري في الواجهة.

## تشغيل الواجهة والفحوص

```powershell
npm ci

npm run lint

```

المعاينة: http://127.0.0.1:43130/ (استخدم نفس أصل المتصفح لاسترجاع المسودات القديمة).

لمزامنة وظائف Development عند تعديلها:

لا تستخدم `convex deploy` أو `--prod` لهذه المرحلة. CLI يعرض بيئة المشروع المستهدف قبل العمل. إعادة البناء محليًا لا تعني نشر Production.

## الإعداد عند نقل المشروع

انسخ `.env.example` إلى `.env.local` واضبط المتغيرات العامة: `VITE_CONVEX_URL`، `VITE_CONVEX_SITE_URL`، `VITE_CLERK_PUBLISHABLE_KEY` (تجريبي `pk_test_`)، و`CONVEX_DEPLOYMENT` الذي يشير إلى Development. لا تضف مفاتيح نشر أو Google أو أسرار Clerk.

في Clerk Development فعّل تكامل Convex؛ في Convex Development اضبط:

- `CLERK_JWT_ISSUER_DOMAIN`: رابط Frontend API الخاص بنسخة Clerk التجريبية.
- `OWNER_SUBJECT`: User ID لحساب المالك داخل تطبيق Clerk، وليس معرّف حساب لوحة إدارة Clerk.
- `CLIENT_ORIGINS`: أصول المعاينة المسموح بها، مفصولة بفواصل؛ حاليًا `http://127.0.0.1:43130,http://localhost:43130`.

إعداد ناقص للمصادقة يغلق الوصول. مستخدم مسجل مختلف لا يحصل على البيانات أو الملفات. كل query/mutation/action عامة تتحقق من المالك على الخادم؛ حماية الواجهة وحدها ليست حد الأمان.

## الملفات الرئيسية

- `src/main.tsx`: الواجهة الأصلية، المسودات المحلية، النموذج وإرسال نسخة محفوظة.
- `src/data.ts`: IndexedDB القديم دون مسح أو تغيير رقم نسخته.
- `src/cloud.tsx`: المصادقة، الاشتراك المباشر بالطلبات، رفع الملفات والتقدم، النقل والمعاينة والتنزيل.
- `shared/validation.ts`: قيود النموذج والملفات والتوقيعات.
- `convex/schema.ts`: الطلبات ومعلومات الرفع والفهارس.
- `convex/requests.ts`: حفظ/إرسال الطلب، ربط الفيديو اليدوي، عقد نتائج المشغّل القادم.
- `convex/files.ts`: إذن الرفع، فحص الخادم للمحتوى والحجم وبصمة SHA-256، وربط storage ID.
- `convex/http.ts`: إرجاع بايتات الملف فقط بعد مصادقة المالك.
- `convex/requests.test.ts`: اختبارات محلية لوظائف Convex عبر convex-test؛ ليست بديلًا عن اختبار البيئة الحقيقية.
- `scripts/check-anonymous.mjs`: فحص حي للرفض المجهول، شغّله بـ`node --env-file=.env.local scripts/check-anonymous.mjs`.

## سلوك الحفظ والتكرار

تُحفظ نسخة IndexedDB قبل الإرسال بما فيها الملفات وعدد المقاطع والتواريخ. يستخدم معرّف المسودة كمفتاح idempotency ثابت في Convex. زر النقل يحتفظ بالنسخة المحلية حتى بعد النجاح؛ النقل ينشئ/يحدث مسودة سحابية، ثم إرسال نفس المسودة يحولها إلى «بانتظار التشغيل». الطلب المرسل لا يُستبدل بتكرار الإرسال. لإنشاء إعلان مختلف اختر «إعلان جديد». الطلب نفسه يُعاد عند إعادة المحاولة بعد انقطاع الاتصال.

رفع الملفات يستخدم بصمة المحتوى كمفتاح ثابت؛ الرفع المتحقق منه يعاد استخدامه. حاجز فوري وزر معطل يمنعان العمليات المتزامنة في الواجهة. انقطاع الشبكة أثناء mutation قد يجعل نتيجة العملية غير معروفة مؤقتًا؛ بعد العودة أعد إرسال نفس المسودة وسيعاد نفس الطلب. الملفات غير المرتبطة الناتجة عن انقطاع أثناء رفع البايتات قد تبقى في تخزين Development؛ لم تنفذ عمليات حذف تلقائي.

## حماية الصور والفيديو

الصور PNG/JPG/WebP حتى 10 MB، وبحد أقصى 8 مراجع. MP4 حتى 100 MB؛ العرض والتنزيل على أجزاء محمية 8 MB كي لا تتجاوز استجابة Convex HTTP حدودها. التحقق في الواجهة والخادم يشمل النوع، الحجم، توقيع البداية وبصمة الملف. فحص التوقيع لا يضمن سلامة كل إطارات الفيديو؛ ظهور خطأ تشغيل يوضح استخدام H.264/AAC.

لا يعاد أي `storage.getUrl` عام. تُجلب الملفات عبر `/files` مع Authorization ثم تعرض من Blob URL مؤقتة وتُلغى عند تغيير الملف أو الخروج. فيديو الطلب المرفوع يدويًا موضح بأنه يدوي، وحالته «مكتمل» تخص هذا الملف. لا يؤكد أي استهلاك نقاط توليد.

رفع الفيديو يتم من لوحة معاينة الطلب بعد اختيار «عرض». الملفات تحفظ كمعرفات Convex، وليس Base64 أو localStorage. النقاط المتوقعة والفعلية حقول مستقلة اختيارية؛ لا يوجد تسعير مفترض.
